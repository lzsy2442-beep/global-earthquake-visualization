# 全球地震可视化 · 部署方案总览

> 最后更新：2026-11-25
> 本文说明站点跑在哪些服务上、数据存在哪、怎么发布、花多少钱、有哪些风险。
> 结构对齐 `E:\9友地图\docs\部署方案总览.md`，便于两个站用同一套心智维护。

---

## 一、一句话概括

**域名在阿里云，DNS 与托管在 Cloudflare（免费版），代码托管在 GitHub，纯静态、零运行时。**

没有服务器，也没有 Worker 脚本：`site/` 目录打包成 Cloudflare 的静态资源，由边缘节点直接返回；GitHub 推一次，Cloudflare 自动部署一次。

与 9友地图 的区别：那边有 Worker + D1 + 邮件，是一个应用；这边只有静态资源，是一个展板。

## 四、计算与存储

### 1. Workers 静态资源（免费版）

| 项 | 值 |
|---|---|
| Worker 名称 | `earthquake-visualization` |
| 线上地址 | https://earthquakevisualization.top |
| 默认域 | https://earthquake-visualization.lzsy2442.workers.dev |
| 是否有脚本 | **无**（`wrangler.jsonc` 里只有 `assets`，没有 `main`） |
| 配置入口 | `wrangler.jsonc` |
| 资源目录 | `./site` |
| 404 处理 | `not_found_handling: "404-page"` → `site/404.html` |
| 文件数 | 9 个（上限 20,000） |
| 最大单文件 | 13.93 MB（上限 25 MiB） |
| 请求计费 | 静态资源请求**免费且不限量**，不占 Worker 的 10 万次/天 |

### 2. 存储

没有数据库。三份数据在构建阶段就被写进 HTML：

| 数据 | 形态 | 体积 |
|---|---|---|
| M5 1995–2026 | 紧凑 JSON 内联 | 6.85 MB → 页面 6.93 MB |
| M3 1995–2026 | 18 字节/条二进制 + Base64 内联 | 13.86 MB → 页面 13.93 MB |
| M5 / M3 近 30 天 | `site/data/recent-*.json`，**每日增量** | 21 KB / 169 KB |

历史数据是静态的，只随月度重建变化；近 30 天数据由 GitHub Actions 每天刷新，两者在浏览器里按时间戳合并。

### 3. 每日数据同步

| 项 | 值 |
|---|---|
| 触发器 | GitHub Actions `schedule`，UTC 01:17 = 北京 09:17 |
| 脚本 | `scripts/fetch_recent.py`（只拉上次同步点之后的事件，滚动保留 30 天） |
| 产物 | `site/data/recent-m5.json`、`recent-m3.json` |
| 发布 | 脚本提交 → Cloudflare 检测到 push → 自动重新构建部署 |
| 免费额度 | GitHub Actions 每月 2000 分钟，本任务每次约 30 秒 |

仓库里的 `data/*.json` 是**源数据**，不是线上运行时数据。线上没有"数据层"可维护。

## 五、代码与发布流水线

| 项 | 值 |
|---|---|
| 代码仓库 | GitHub `lzsy2442-beep/global-earthquake-visualization` |
| 主分支 | `main` |
| 发布方式 | **Cloudflare Workers Builds**（连 GitHub，自动构建） |
| 构建命令 | `npx wrangler deploy` |
| 耗时 | 约 1–2 分钟（含 npm install 与 34.7 MB 资源上传） |

推送到 `main` 后，Cloudflare 自动执行：

```
npm install
npx wrangler deploy        # 读取 wrangler.jsonc，上传 site/ 为静态资源
```

> ⚠️ 同 9友地图 的规则：`wrangler.jsonc` 是**权威清单**。
> 本站没有变量和密钥，所以不存在"控制台改的会被覆盖"的问题。

### 与 Pages 的取舍

| 方案 | 配置 | 适合 |
|---|---|---|
| **Workers + Static Assets**（本文采用） | `wrangler.jsonc` + `package.json` | 与 9友地图 同构，将来要加 `/api` 不用搬家 |
| Cloudflare Pages | 控制台点选，无配置文件 | 只想 5 分钟上线，永远不加后端 |

两者额度几乎一致（都是单文件 25 MiB、都不限带宽），差别只在"要不要配置文件"。

## 八、环境变量与密钥

**本站没有环境变量，也没有 Secret。**

这是与 9友地图 最大的结构差异：那边有 Worker，`TDT_TK` 可以作为变量注入、由接口下发给前端；这边是静态 HTML，**key 只能硬编码在页面里**。

| 名称 | 位置 | 值 |
|---|---|---|
| 天地图 key | `site/m5-cluster.html`、`site/m5-points.html`、`site/m3-points.html` 各 1 处 `TDT_TK` | `38fda728573672739075a63f7f380e03` |

**key 可用性已验证**（2026-11-25 从本机直连请求）：

| 请求 | 结果 |
|---|---|
| `vec` 矢量瓦片 + key | `200` / `image/png` / 4310 B |
| `cva` 标注瓦片 + key | `200` / `image/png` / 2265 B |
| 同样的请求不带 key | `418` |

即：key 有效，且没有强制 referer 限制。上线后仍应去天地图控制台确认「域名白名单」，有则把 `earthquakevisualization.top` 加进去。

> 注意：9友地图 用的是另一个 key（`fe6698…`）。**同一个 key 绑两个域名会互相影响配额**，排查问题时也更难定位，两个站各用各的。

## 十、已知风险与待办

| 风险 | 说明 | 应对 |
|---|---|---|
| **国内访问速度** | Cloudflare 免费版无中国大陆节点，首屏 1–3 秒 | 接受；要快只能备案 + 国内云 |
| **无 ICP 备案** | 托管在境外，法律上无需备案 | 迁回国内前必须先备案 |
| **8.24 MB 首屏** | M3 页数据内联，必须下完整个 HTML 才渲染 | 第 2 阶段拆包：页面壳 + 外置数据 + 进度条 |
| **单文件 25 MiB 上限** | 现在是 13.93 MB，若数据继续增长会顶到天花板 | 超限前必须完成数据外置 |
| **天地图 key** | 硬编码、可能绑了旧域名白名单 | 单独申请新 key 并绑定正式域名 |
| **高德瓦片** | 公开接口，可能校验 referer | 被拦则退化为天地图单底图 |
| **单点** | 全靠 Cloudflare 免费版，无 SLA | 页面是纯静态，随时可拖到别处重建，恢复成本极低 |
| **数据出境** | 无用户数据，只有公开地震数据 | 风险很低，无需隐私政策 |

## 十二、如果哪天要搬家

按工作量从轻到重：

1. **只换域名**：加 Cloudflare 自定义域 + 改 `sitemap.xml`/`canonical`/`_headers` 里的绝对地址，约 30 分钟
2. **换成别家静态托管**（Vercel / Netlify / GitHub Pages）：`site/` 原样拖过去即可，**零改代码**，约 20 分钟
3. **迁回国内**（阿里云 OSS + CDN）：需要备案，上传 `site/` 即可，约 1 小时 + 备案 7–20 天
4. **自己写 Worker 加接口**：在现有 `wrangler.jsonc` 里加 `main` 和 `/api` 路由，静态资源不受影响

> 第 2、3 条之所以这么快，是因为**没有运行时**：没有数据库连接串、没有环境变量、没有冷启动。
> 这是纯静态站点相对 9友地图 那种应用的最大红利——搬家的成本几乎为零。
