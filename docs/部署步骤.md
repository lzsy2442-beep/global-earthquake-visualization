# 部署步骤 · 从零到 https://earthquakevisualization.top

> 照着做即可，不用理解原理。原理见 [部署方案总览](部署方案总览.md)。
> 总耗时：**60–90 分钟**，其中 10–30 分钟是在等 DNS 生效，可以先去干别的。

**路线**：阿里云买的域名 → NS 交给 Cloudflare → 代码放 GitHub → Cloudflare 连仓库自动部署 → 绑域名。

**全程花费**：0 元（域名年费已付）。

---

## 0. 开工前：确认本地能跑

在开始之前，先确认站点在你电脑上是好的。打开 PowerShell：

```powershell
cd D:\LZSY\地震汇编\site
E:\python\python.exe -m http.server 8080
```

浏览器打开 <http://127.0.0.1:8080>，确认三件事：

- [ ] 首页能打开，三张卡片都在
- [ ] 点「进入聚类视图」，地图能出图（说明天地图 key 有效）
- [ ] 点一个震点，能弹出详情

三条都过了再往下走。跑完按 `Ctrl+C` 关掉，或者直接关窗口。

## 第 1 步 · 域名接入 Cloudflare（约 15 分钟 + 等待）

### 1.1 注册 Cloudflare

打开 <https://dash.cloudflare.com/sign-up>，用邮箱注册并验证。免费，不用绑卡。

### 1.2 添加站点

1. 登录后点右上角 **Add a site**（或 **+ Add** → **Existing domain**）
2. 输入 `earthquakevisualization.top`，点 **Continue**
3. **中间会出现一个 "Additional configuration"（AI 爬虫策略）页面**，见下方 1.2.1
4. 套餐选 **Free**，点 **Continue**
5. **Import DNS records** 保持 **Automatic**（新域名通常扫不出记录，正常）
6. 记下页面给出的 **两条 nameserver**（见 1.2.2），下一步要用

#### 1.2.1 Additional configuration 怎么选

| 选项 | 选什么 | 理由 |
|---|---|---|
| I monetize pages that serve ads | **不勾** | 站点没有广告 |
| **Search**（搜索引擎爬虫） | **Allow (do not block)** | ⚠️ 唯一不能错的一项。改成 Block 等于让 Google/百度 别收录你 |
| Training（AI 训练爬虫） | Allow 或 Block 都行 | 不影响站点运行，也不影响收录；介意内容被拿去训练就选 Block |
| Agents（代用户访问的 AI） | Allow | 否则部分 AI 助手打不开你的页面 |
| 各家 Personal Agents | Allow | 同上 |
| **Enable Bot Preference Sync** | **建议关掉** | 它会把 Cloudflare 的策略**自动拼接到 robots.txt 前面**，导致线上 robots.txt 与仓库里的文件不一致，以后排查问题很麻烦 |

> 这些设置**随时可以改**（站点激活后：Security → Bots / AI Crawl Control），不用在这里纠结太久。
> 只有 **Search = Allow** 这一项是必须对的。

#### 1.2.2 下一步：NS 记录

页面给出两条 nameserver，形如：

```
xxxx.ns.cloudflare.com
yyyy.ns.cloudflare.com
```

**把这两条复制到记事本**，下一步要用。

#### 1.2.3 DNS 记录页面：留空，直接继续

如果出现 **"No DNS records"** 以及三条提示（MX / www / 根域），**一条都不用加**，直接点 **Continue to activation**。

| 提示 | 处理 |
|---|---|
| "To receive email at @… add an MX record" | 忽略，本站不收发邮件 |
| "A record for the www subdomain is required…" | 忽略，第 4 步给 Worker 绑自定义域时会自动创建 |
| "A record pointing to the root domain is required…" | 同上 |

> 现在手动加一条指向任何 IP 的 A 记录，会和后面自动创建的记录冲突，反而要回来删。

### 1.3 到阿里云改 NS

1. 打开 <https://dc.console.aliyun.com> → **域名列表**
2. 找到 `earthquakevisualization.top`，点右侧 **管理**
3. 左侧菜单找 **DNS 修改**（有的版本叫「DNS 服务器」/「修改 DNS」）
4. 选 **修改为其他 DNS 服务器**（自定义）
5. 把 Cloudflare 给的两条 NS 分别填进去，**删掉阿里云原来的两条**
6. 确认提交

> ⚠️ 前提：域名必须已完成**实名认证**，否则阿里云不允许改 NS，解析也会被暂停。

### 1.4 等生效

回到 Cloudflare 网站概览页，状态会从 `Pending Nameserver Update` 变成 **`Active`**。

一般 10 分钟到 2 小时，最长 24 小时。想主动查：

```powershell
nslookup -type=NS earthquakevisualization.top 8.8.8.8
```

看到输出里是 `*.ns.cloudflare.com` 就说明生效了。

**完成标志**：Cloudflare 站点状态显示 **Active**（绿色）。

## 第 2 步 · 代码推到 GitHub（约 20 分钟）

### 2.1 装 Git

```powershell
winget install --id Git.Git -e --source winget
```

装完**关掉 PowerShell 重新打开**（否则找不到 `git` 命令），验证：

```powershell
git --version
```

### 2.2 配置身份

```powershell
git config --global user.name "lzsy2442-beep"
git config --global user.email "你的GitHub邮箱"
git config --global core.quotepath false
git config --global init.defaultBranch main
```

最后一条很重要：不加的话，`项目说明.md` 会在 `git status` 里显示成一串 `\344\270...`。

### 2.3 本地初始化并提交（分三批）

```powershell
cd D:\LZSY\地震汇编
git init
git add README.md LICENSE CITATION.cff .gitignore .gitattributes wrangler.jsonc package.json 项目说明.md 网站实施路径.md docs scripts
git commit -m "docs: 项目说明、部署方案与构建脚本"

git add site
git commit -m "feat: 站点页面（首页 + 三个视图 + 404 + 离线版）"

git add data/*.json
git commit -m "data: 处理后的 M5/M3 紧凑数据集"
```

**为什么要分三批**：仓库一共约 61 MB，国内一次推 61 MB 容易断在半路；分三批断了只重推当前一批。

**预期**：第三次提交后 `git log --oneline` 能看到三条记录。

### 2.4 在 GitHub 建空仓库

1. 打开 <https://github.com/new>
2. Repository name：`global-earthquake-visualization`
3. 选 **Public**
4. **不要**勾 "Add a README file"、**不要**选 .gitignore 模板（本地已经有了，勾了会冲突）
5. 点 **Create repository**

### 2.5 推送

```powershell
git remote add origin https://github.com/lzsy2442-beep/global-earthquake-visualization.git
git push -u origin main
```

弹出登录框时：

- **用户名**填 GitHub 用户名
- **密码**要填 **Personal Access Token**，不是账号密码（GitHub 2021 年起停用了密码推送）

生成 Token：GitHub → 右上角头像 → **Settings** → 左侧最下 **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)** → 勾选 **`repo`** → 生成后**立刻复制**（只显示一次）。

> 嫌麻烦就用 [GitHub Desktop](https://desktop.github.com/)：登录后直接 Publish，不用管 token。

**如果卡住或超时**：说明到 github.com 的连接不稳。改用 GitHub Desktop，或者设置代理后再推。不要反复重试同一个大包。

**完成标志**：仓库页面能看到 `site/`、`wrangler.jsonc`、`README.md`，且 README 能正常渲染出截图。

## 第 3 步 · Cloudflare 连接仓库，自动部署（约 10 分钟）

### 3.1 创建 Worker 并连仓库

1. Cloudflare 控制台左侧 **Workers & Pages**
2. **Create application** → 选 **Workers** 标签 → **Import a repository**（新版界面可能叫 **Connect to Git**）
3. 第一次会要求授权 GitHub：点 **Connect GitHub** → 只勾选 `global-earthquake-visualization` 这一个仓库 → **Install & Authorize**
4. 回到列表，选中这个仓库，点 **Begin setup**

### 3.2 填写构建配置

| 字段 | 填什么 |
|---|---|
| Project name | `earthquake-visualization`（要和 `wrangler.jsonc` 里的 `name` 一致） |
| Root directory | **留空** |
| Branch | `main` |

**命令怎么填，看界面有几个输入框：**

| 界面形态 | Build command | Deploy command |
|---|---|---|
| 只有一个框 | `npx wrangler deploy` | 不存在 |
| 有 Build + Deploy 两个框 | **留空** | 保持默认 `npx wrangler deploy` |

两种写法等价，别把同一条命令填两次（会部署两遍）。然后点 **Deploy**。

> 为什么是这条命令：`wrangler.jsonc` 里没有 `main`，只有 `assets.directory = "./site"`，所以这是一次「只上传静态资源」的部署。Cloudflare 会自动先跑 `npm install`（装 wrangler），再跑部署命令。

### 3.3 看构建日志

点进 **Deployments** → 最新一条 → **View build**。第一次大约 **2–4 分钟**（要传 34.7 MB 资源）。

日志末尾应该出现类似：

```
Uploaded earthquake-visualization (x.xx sec)
Deployed earthquake-visualization triggers
  https://earthquake-visualization.<你的子域>.workers.dev
```

### 3.4 先用 workers.dev 验证

打开日志里那个 `*.workers.dev` 地址，确认首页能开、地图能出图。

**这一步先过，再去绑域名**——否则绑完域名出问题，分不清是域名的问题还是部署的问题。

**完成标志**：`*.workers.dev` 地址能正常打开三个页面。

## 第 4 步 · 绑定域名（约 5 分钟）

### 4.1 加自定义域

1. Workers & Pages → `earthquake-visualization` → **Settings** → **Domains & Routes**
2. **Add** → **Custom domain**
3. 输入 `earthquakevisualization.top` → **Add domain**
4. 再重复一次，加 `www.earthquakevisualization.top`

因为域名的 NS 已经在 Cloudflare，DNS 记录会自动创建，不用手动加。证书签发通常 1–3 分钟。

### 4.2 把 www 跳转到主域名（可选但建议）

避免同一内容两个地址，影响搜索引擎收录：

1. Cloudflare 左侧 **Rules** → **Redirect Rules** → **Create rule**
2. 名称：`www to apex`
3. **When incoming requests match**：
   - Field：`Hostname`
   - Operator：`equals`
   - Value：`www.earthquakevisualization.top`
4. **Then**：
   - Type：`Static`
   - URL：`https://earthquakevisualization.top`
   - Status code：`301`
   - 勾选 **Preserve query string**
5. **Deploy**

### 4.3 打开严格 HTTPS

**SSL/TLS** → **Overview** → 模式选 **Full (strict)**；**Edge Certificates** 里打开 **Always Use HTTPS**。

**完成标志**：<https://earthquakevisualization.top> 能打开，浏览器地址栏是小锁。

**位置**：`site/m5-cluster.html`、`site/m5-points.html`、`site/m3-points.html` 各一处，变量名 `TDT_TK`。三个页面各 1 处，共 3 处。

| 请求 | 结果 |
|---|---|

| `cva` 标注瓦片 + 该 key | `200`，`image/png`，2265 字节 ✅ |
| 同样的请求**不带** key | `418` ❌（说明 key 确实在起作用） |

也就是说：**key 有效、没有强制 referer 限制**。但仍建议上线后去控制台做两件事：

1. 打开 <https://console.tianditu.gov.cn> → **应用管理** → 找到这个 key

> ⚠️ 不要和 9友地图 的 key（`fe6698…`）混用。两个站共用一个 key 会互相消耗配额，出问题时也更难定位。

**地图空白时怎么查**：按 `F12` → **Network** → 过滤 `tianditu` → 看状态码。

- `200` 但没图 → 样式或容器问题
- `403` / `418` → key 失效或域名不在白名单
- 请求根本没发出 → 页面 JS 报错，看 Console 面板

## 第 8 步 · 故障排查

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| Cloudflare 一直 Pending | 阿里云 NS 没改成功 / 域名未实名 | 重新检查 1.3，用 `nslookup` 确认 |
| 构建失败，报 `wrangler: not found` | 没识别成 Node 项目 | 确认 `package.json` 已在仓库根目录 |
| 构建失败，报 `assets directory not found` | 目录大小写或路径不对 | `wrangler.jsonc` 里是 `./site`，核对仓库里有 `site/` |
| 部署成功但页面 404 | 资源目录指错了 | 看 Deployments 日志里上传了多少个文件，应该是 9 个 |
| 地图一片灰，无瓦片 | key 不在白名单 / 域名没生效 | 按第 7 步查 Network |
| 官网打开很慢 | 走的是境外节点 | 正常现象；第 2 阶段拆包后改善 |
| `git push` 卡在 writing objects | 国内到 GitHub 网络不稳 | 换 GitHub Desktop，或分批推 |
| 页面打开是旧版本 | 浏览器缓存（HTML 缓存 5 分钟） | 强制刷新 `Ctrl+F5` |

## 第 9 步 · 万一要下线或搬家

- **临时下线**：Worker → Settings → Domains & Routes → 删掉自定义域，站点立刻从公网消失，但资源还在

- **搬到别处**：`site/` 目录原样拖给 Vercel / Netlify / 阿里云 OSS 即可，**不用改一行代码**
